# Adding a feature to DyNeo

## Overview

A feature lands in **one commit with everything around it**. A module without
its shim, spec, help, mapping or health entry is unfinished, not "a first
step". Copy the shape of a small existing tool (`tools.matrix`:
`lua/tools/matrix.lua`, `plugin/matrix.lua`, `tests/spec/tools/matrix_spec.lua`)
instead of inventing one.

## The commit, file by file

Fill every row; write "n/a" in the report only for a row that truly does not
apply (no binary → no health entry).

| # | File | Contents |
|---|------|----------|
| 1 | `tests/spec/tools/<name>_spec.lua` | written first and seen failing on an assertion (against a stub `lua/tools/<name>.lua` returning `{}`, not on a missing module); `h.unload('tools.<name>')` in `before_each`; a fake CLI on a private `$PATH` via `h.tmpdir`, never the machine's |
| 2 | `lua/tools/<name>.lua` | `local M = {}`; tunables as `M.TIMEOUT`, `M.LIMIT`; CLIs through `util.system.run(cmd, opts, on_done)` (deadline, `max_bytes`); the callback handles `result.missing`, `result.timed_out`, a failure via `util.system.failure(result, name)`, and says so when `result.cut`; output in `util.scratch.open(lines, opts)` (a new tab unless `opts.split` says otherwise); messages via `util.notify.titled('<area>')` |
| 3 | `plugin/<name>.lua` | a few lines: `nvim_create_user_command('Dy<Name>', function() require('tools.<name>')...)`; nothing heavy at startup, works under `nvim --clean` |
| 4 | `tests/spec/util/<x>_spec.lua` | for each new `lua/util/<x>.lua` |
| 5 | `doc/dyneo.txt` | a section (ruled with dashes, never `=====`), the command in `|dyneo-commands|`; `scripts/keymaps-doc.sh` (row 7) also runs `helptags`; commit `doc/tags` |
| 6 | `lua/config/keymaps.lua` or the spec's `keys` | via `map`, under the area's group (`<leader>i` infra, `<leader>k` supply chain/secrets, `<leader>p` project) or a buffer-local `<localleader>` in the ftplugin; look the lhs up in `doc/dyneo-keymaps.txt` first |
| 7 | `doc/dyneo-keymaps.txt` | regenerated by `scripts/keymaps-doc.sh`, never edited |
| 8 | `lua/dyneo/health.lua` | each external binary in `requirements()`: `on_demand` for a CLI one command asks for (info when absent), `optional` for one many features use (warning) |
| 9 | `README.md` | at most a row or phrase in the feature table |

## Before writing code

- `git worktree list` and `git log main..<branch> --name-only`: another
  session may be editing `keymaps.lua`, `health.lua` or `doc/dyneo.txt`.
- Destructive or untrusted actions (applying, running a file's blocks,
  overwriting) ask first and do exactly what was shown.
- Anything that may carry secrets passes `util.sensitive` / `util.ai_guard`.

## Finish

Commit `feat(<name>): <outcome a user sees>`, lower case, no trailers. Then
**REQUIRED SUB-SKILL:** use `dyneo-checks` before reporting.

## Common mistakes

| Mistake | Fix |
|---|---|
| `vim.system(...):wait()` in the command | `util.system.run` with a callback |
| Mapping on a key already taken (`<leader>ip` is pod logs) | `rg -F '<lhs>' doc/dyneo-keymaps.txt` |
| Help edited, `doc/tags` not regenerated | run `scripts/keymaps-doc.sh`, commit `doc/tags` |
| Rationale pasted into README | it belongs in the help and module comments |
